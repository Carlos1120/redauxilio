## Historia y límite

Como ciudadano autenticado, quiero publicar un punto de asistencia o una vía afectada para compartir su situación y ubicación. Trazabilidad: RF-06 para base común y puntos/vías; RF-07 para ubicación manual, geolocalización con permiso y búsqueda de lugar/dirección; RN-04, RN-05, RN-24, RN-25, RN-28 y RNF-07/08 indicados en la tarjeta. RA-09 y RA-11 completarán las otras categorías de RF-06; RA-12 incorporará fotografías. No presentar RA-03 como cumplimiento total de RF-06 ni como fuente oficial de emergencias.

El alcance funcional de esta historia se limita a puntos de asistencia y vías. No se solicitan documentos personales, historias médicas, domicilios privados ni contacto público. Si más adelante se incorpora contacto, deberá existir autorización y retiro posterior. La confianza inicial es **Reportada**; no se asigna confirmación comunitaria u oficial automáticamente. La consulta de RA-02 mantiene sus datos sintéticos y deberá incorporar publicaciones nuevas sin alterar la regla de visibilidad del servidor.

## Criterios observables

| Caso                      | Entrada y acción                                                                                        | Resultado esperado                                                                                                                 |
| ------------------------- | ------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| Acceso                    | Visitante sin sesión intenta publicar                                                                   | El servidor rechaza la escritura; la consulta pública sigue funcionando.                                                           |
| Punto válido              | Cuenta activa envía subtipo refugio, acopio o centro médico; nombre, disponibilidad y ubicación válidos | Se crea una sola publicación con autor, coordenadas editables, fecha, estado y confianza Reportada; aparece en consulta y detalle. |
| Vía válida                | Cuenta activa envía tramo, tipo de afectación, transitabilidad y ubicación válidos                      | Se crea una sola vía con los mismos datos comunes, visible en mapa, lista y detalle.                                               |
| Campos inválidos          | Falta un dato obligatorio, hay coordenadas fuera de rango o un subtipo incompatible                     | HTTP 400 con mensaje útil; no queda una fila parcial.                                                                              |
| Límite                    | La misma cuenta intenta crear la sexta publicación dentro de una hora                                   | El servidor rechaza la sexta, incluso con peticiones concurrentes; otra cuenta conserva su cuota.                                  |
| Ubicación manual          | Elegir punto en mapa o escribir coordenadas y luego corregirlas                                         | El valor final confirmado es el que se guarda; el mapa no bloquea el formulario si falla.                                          |
| Ubicación del dispositivo | Aceptar o denegar permiso del navegador                                                                 | Con permiso se propone una coordenada editable; sin permiso siguen disponibles mapa y campos manuales.                             |
| Búsqueda                  | Buscar lugar/dirección mediante el proveedor elegido y seleccionar resultado                            | Se propone una coordenada editable con atribución visible; sin proveedor/red/resultados la selección manual sigue disponible.      |
| Conexión                  | Intentar publicar sin conexión o con error del servidor                                                 | No se anuncia publicación exitosa; el borrador local se conserva para reintentar.                                                  |

## Diseño técnico propuesto para revisión

- Mantener Spring Boot, Thymeleaf, JavaScript/CSS propios, Leaflet y PWA. Reutilizar `.draft-section`, `.field`, botones, tokens de `app.css`, Onest y rojo `#d7262e`; la selección del punto ocurre sobre el mapa existente.
- Agregar almacenamiento persistente independiente de los seis ejemplos de RA-02. La fila nueva referencia el ID de la cuenta autenticada; la API pública entrega un DTO sin correo ni datos internos del autor. Validar categoría, campos por subtipo y coordenadas tanto en servidor como en formulario.
- Hacer la creación transaccional. Para cumplir cinco publicaciones por cuenta en una ventana móvil de una hora aun con concurrencia, serializar por cuenta en la base de datos antes de contar e insertar. Probar límite exacto, dos cuentas y peticiones concurrentes; no confiar en JavaScript para la cuota.
- El formulario permite corregir siempre latitud y longitud. La geolocalización del navegador requiere acción de la persona y permiso; no se ejecuta al abrir la página. La búsqueda se activa mediante botón, nunca como autocompletado continuo.
- Santiago eligió Nominatim público para esta demostración. La integración debe usar un proxy del servidor con URL configurable, identificación de la aplicación, atribución visible, caché y límite global máximo de una petición por segundo en la instancia. No enviar consultas automáticas ni de carga al proveedor. Un fallo o ausencia de resultados mantiene la selección manual.
- Conservar el borrador en IndexedDB. El service worker no intercepta escrituras y un error de red no borra el borrador ni muestra éxito. No incluir fotos, datos personales sensibles o rutas de edición/cierre en este PR.

## Implementación y comprobaciones del 14 de octubre de 2026

La rama `feat/RA-03-publicacion-georreferenciada` nace de `origin/develop` `125d93a`. `citizen_publication` persiste puntos y vías con autor interno, campos específicos, fechas, confianza pública Reportada y coordenadas. El servicio valida datos, bloquea la fila de cuenta y cuenta una ventana móvil de una hora dentro de la misma transacción. La consulta y el detalle públicos combinan los seis ejemplos iniciales con las filas visibles sin publicar correo ni ID de autor.

El formulario conserva borradores parciales en IndexedDB y guarda el estado antes de intentar publicar. Permite elegir coordenadas en el mapa, proponerlas por GPS con permiso, buscarlas a petición o escribirlas. El proxy de Nominatim identifica la aplicación, guarda hasta 200 búsquedas durante 24 horas y espera al menos un segundo desde el fin de la consulta de red anterior **por instancia**. En una instalación con varias instancias se necesita un limitador compartido antes de usar el servidor público. La búsqueda no es requisito para publicar: si falla, queda la selección manual. `sw.js` precarga el nuevo script y sigue sin interceptar escrituras.
