Solo el autor autenticado mantiene sus publicaciones visibles persistidas. La API privada usa la identidad de la sesión, nunca un autor enviado por el cliente. Otra cuenta, un ID inexistente o un caso oculto obtienen 404; un visitante obtiene 401 en `/api/my/**`; escrituras sin CSRF obtienen 403. Respuestas privadas sin caché; ejemplos del mapa no son editables. No hay permisos de operador, eliminación, verificación ni confirmaciones RA-05.

| Ruta                                    | Operación                                                         |
| --------------------------------------- | ----------------------------------------------------------------- |
| `GET /api/my/publications`              | Lista propia, incluidos cerrados                                  |
| `PATCH /api/my/publications/{id}`       | Contenido y coordenadas de caso abierto, misma categoría y estado |
| `POST /api/my/publications/{id}/status` | Transición explícita; motivo obligatorio al reabrir               |
| `GET /api/my/publications/{id}/history` | Historial privado con fecha, acción, antes/después y motivo       |

## Matriz acordada

| Categoría  | Desde                   | Destinos permitidos                            |
| ---------- | ----------------------- | ---------------------------------------------- |
| Asistencia | DISPONIBLE              | CAPACIDAD LIMITADA, LLENO, CERRADO             |
| Asistencia | CAPACIDAD LIMITADA      | DISPONIBLE, LLENO, CERRADO                     |
| Asistencia | LLENO                   | DISPONIBLE, CAPACIDAD LIMITADA, CERRADO        |
| Asistencia | CERRADO                 | DISPONIBLE, CAPACIDAD LIMITADA; con motivo     |
| Vía        | BLOQUEADA               | PARCIALMENTE HABILITADA, HABILITADA            |
| Vía        | PARCIALMENTE HABILITADA | BLOQUEADA, HABILITADA                          |
| Vía        | HABILITADA              | BLOQUEADA, PARCIALMENTE HABILITADA; con motivo |

Un estado repetido, desconocido o de otra categoría es inválido. CERRADO no pasa directamente a LLENO. Cerrar conserva detalle y auditoría; la consulta pública solo incluye cerrados al solicitarlos. Los cerrados no admiten edición libre.

**Coherencia vial:** HABILITADA es el estado terminal/cerrado de la matriz, no «carretera físicamente bloqueada». Las altas nuevas HABILITADA guardan `closed=true`. Los registros antiguos HABILITADA con bandera falsa se interpretan como cerrados al consultar y autorizar mantenimiento, sin borrar ni reescribir filas históricas. Su reapertura motivada registra antes/después y vuelve a guardar una bandera coherente. La creación inicial conserva fecha de alta; no inventa una modificación anterior.

## Arquitectura y garantías

Se conservan controlador, servicio transaccional, JDBC y el DTO de RA-03. El bloqueo `FOR UPDATE` por publicación serializa escritura y lectura previa de auditoría. Dos cierres iguales concurrentes producen un cierre y un rechazo, con una entrada de historial. Las ediciones se aplican en orden de bloqueo, sin control optimista de versión: el último escritor puede reemplazar contenido, conservando sus fotografías auditadas. No se promete detección de formularios obsoletos entre dispositivos. Falla de inserción de auditoría revierte edición/estado en la misma transacción.

El JS de gestión es un recurso público; `/api/my/**` sigue protegido. `identity-forms.js` comunica una acción de acceso; `identity-status.js` confirma y emite una notificación de estado consumida por `app.js` y la gestión privada, sin recursión. Versiones de sesión, lista e historial descartan respuestas obsoletas, incluso durante CSRF o escrituras. Logout/401/403 y desconexión limpian campos, selección e historial. Al reconectar se ocultan datos hasta confirmar sesión; una respuesta antigua del perfil tampoco repuebla nombre/correo. Solo un cambio interactivo de acceso abre el modal; la sincronización de fondo no roba el foco.

El historial muestra diferencias de campos conocidos como texto, nunca HTML ni JSON ejecutable. Los cambios fallidos conservan la corrección para reintentar. No se guardan escrituras pendientes ni datos privados en IndexedDB o Cache Storage. El SW v16 precarga los scripts públicos y sigue excluyendo rutas privadas, `/csrf` y métodos de escritura. El borrador de RA-03 es independiente; cartografía externa requiere conexión.

La interfaz reutiliza Onest, rojo y formularios de `app.css`. La cabecera de gestión se apila para evitar desbordamiento móvil. No cambia la dirección visual ni requiere una biblioteca nueva.
