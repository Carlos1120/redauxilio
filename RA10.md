# RA-10 · Avistamientos

## Alcance funcional

Un avistamiento es una observación ciudadana vinculada a un caso público de persona desaparecida; no es una categoría independiente. Registra fecha y hora observadas, sector público, coordenadas aproximadas, descripción y hasta tres fotografías opcionales. La consulta se incorpora al detalle e historial del caso. El registro nunca cambia automáticamente el estado del caso.

La autoría se conserva en SQL para trazabilidad, pero el historial público no expone cuenta, correo ni nombre del autor. Las coordenadas se redondean a tres decimales y los textos reutilizan la detección de datos privados de RA-09. Las consultas e imágenes responden `no-store` y permanecen fuera del caché del service worker.

## Reglas de este incremento

- Solo una publicación visible de categoría `MISSING_PERSON` admite historial público.
- Para añadir observaciones se requiere sesión ciudadana y CSRF.
- Por seguridad, solo se admiten nuevos registros mientras el caso esté `DESAPARECIDA` y no cerrado. La fuente original no especifica qué hacer con casos encontrados/cerrados: se presenta como política propuesta para revisión de Carlos.
- Fecha futura, coordenadas no finitas/fuera de rango, texto vacío/excesivo o con datos sensibles se rechazan.
- Imágenes opcionales reutilizan validación, decodificación y límites de RA-12; máximo tres de 5 MiB cada una.
- El alta de observación e imágenes es transaccional. Ninguna operación actualiza `operational_status`, `closed` ni `updated_at` del caso.

## Verificación y límites

`MissingPersonSightingTests` acepta H2 en memoria por defecto o una base PostgreSQL aislada mediante `RA10_TEST_DB_URL`, `RA10_TEST_DB_USERNAME` y `RA10_TEST_DB_PASSWORD`. La clase ejecuta `schema.sql` y elimina sus fixtures antes de cada caso: al usar PostgreSQL, la base debe ser nueva y exclusiva para pruebas. En PowerShell, exporta esas tres variables y ejecuta `.\mvnw.cmd -B '-Dtest=MissingPersonSightingTests' test`. La ejecución real con PostgreSQL 18.3 pasó 4/4 y cubrió alta HTTP multipart, lectura pública/foto, privacidad, CSRF, rechazo de estados inválidos y rollback de la observación si falla el guardado de la foto.

Maven verify, Node y formato se ejecutan antes de actualizar el PR; el CI se vuelve a comprobar para el HEAD publicado. Revisión visual y aprobación formal de Carlos siguen pendientes. Los detalles reproducibles están en `EVIDENCIAS.md` y el PR.
