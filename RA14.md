Base: develop 201910dafc39bea291edf3a08089d507d5763634. RF-18, RN-26 y RN-27. Tarjeta https://trello.com/c/i9FK7pfi. Incremento verificado para PR Draft; aceptacion humana e integracion pendientes.

## Contrato confirmado

ASSISTANCE, ROAD y HELP_REQUEST: misma categoria (no subtipo), distancia Haversine <=250m y creacion entre ahora-24h y ahora inclusive. Futuras y ocultas no se ofrecen; cerradas geograficas advierten dentro de esa ventana porque RN-26 no las excluye.

MISSING_PERSON: caso visible y no cerrado, sin limite de distancia/24h. A: nombre o referencia normalizados iguales. B: edad informada e igual, sector normalizado igual y descripcion fisica normalizada igual/no vacia. Fecha/hora de ultima vez vista es contexto, no una condicion de coincidencia. Normalizacion NFD, sin marcas diacriticas, minusculas, puntuacion y espacios repetidos normalizados; sin similitud difusa.

Solo advertencia: no fusionar, cerrar, ocultar ni borrar automaticamente. Al existir coincidencia, motivo privado de1–500 caracteres, validado por el servidor y con minimizacion de datos sensibles. Falta de motivo produce409; exceso o texto sensible400. Sin coincidencia sigue el flujo normal.

## Flujo y arquitectura

Formulario → POST privado `/api/my/publications/possible-duplicates` (sesion/CSRF/no-store) → coincidencias publicas minimas → abrir detalle en otra pestaña o justificar → guardado final vuelve a comprobar → commit de publicacion/justificacion/fotos. Una comprobacion fallida no se convierte en cero coincidencias. Cambiar campos invalida el motivo y una respuesta tardia no publica datos anteriores. Cancelar/error conserva borrador; exito solo tras201.

`PublicationCreationService` protege ambos endpoints de alta. Bloquea autor para cuota y despues una fila de guardia por categoria para duplicados; la guarda se mantiene hasta commit/rollback. Autores diferentes de la misma categoria no pueden confirmar simultaneamente dos altas coincidentes sin motivo. Las cuatro categorias no comparten una unica guardia. Lectura y escritura usan la misma transaccion Spring/JDBC. Fallo en imagen o persistencia revierte tambien la justificacion.

Candidatos: SQL parametrizado filtra categoria, visibilidad, fecha/latitud para geograficos o casos abiertos para desaparecidos. Se leen bloques de200 mediante cursor por ID y se devuelven como maximo20 coincidencias, sin fotos, autores, contactos ni auditoria. No materializa la base completa. Los desaparecidos requieren comparacion Unicode en Java: coste proporcional a casos abiertos recorridos; indices y bloques acotan memoria, pero no hay indice de nombres normalizados. No se afirma rendimiento masivo ni busqueda difusa. La guardia serializa altas de una categoria durante el guardado (incluidas fotos), coste aceptado para el volumen academico; no protege importaciones SQL externas ni constituye deduplicacion universal de ediciones.

La tabla privada `publication_duplicate_justification` no integra DTO, caché publica ni historial visible. Esquema idempotente, indices de candidatos y cuatro filas de guardia sin dependencias nuevas. El enlace `?publication=ID` consulta solo detalle publico vigente. UI reutiliza app.css y controles nativos.
